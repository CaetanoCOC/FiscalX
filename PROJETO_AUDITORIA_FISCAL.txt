VISÃO GERAL
-----------
Construir um sistema profissional de auditoria fiscal em Python com interface
Streamlit. O sistema lê XMLs de Notas Fiscais Eletrônicas (NFe), valida
tributação, detecta inconsistências, apura impostos (ICMS, PIS, COFINS, IPI,
ISS) e gera relatórios de auditoria exportáveis. As alíquotas devem ser
atualizadas em tempo real via APIs e arquivos de configuração versionados.

OBJETIVO FINAL
--------------
Portfólio profissional para vagas de Auditor Fiscal e Analista Fiscal.
O sistema deve impressionar em uma entrevista técnica sendo demonstrado ao vivo.

MÓDULO 1: PARSER DE NFe (core/parser_nfe.py)
================================================================================

OBJETIVO: Ler XMLs de NFe no layout 4.0 e retornar estrutura de dados padronizada.

CAMPOS A EXTRAIR DO XML:

  CABEÇALHO DA NOTA:
  - chNFe          → Chave de acesso (44 dígitos)
  - nNF            → Número da nota
  - serie          → Série
  - dhEmi          → Data de emissão
  - natOp          → Natureza da operação
  - tpNF           → Tipo (0=Entrada, 1=Saída)
  - idDest         → Destino (1=Interna, 2=Interestadual, 3=Exterior)
  - cMunFG         → Código do município do fato gerador (IBGE 7 dígitos)

  EMITENTE (emit):
  - CNPJ / CPF
  - xNome          → Razão social
  - UF             → Estado
  - cMun           → Código município IBGE
  - xMun           → Nome do município
  - CRT            → Regime tributário (1=Simples, 2=Simples Excesso, 3=Normal)

  DESTINATÁRIO (dest):
  - CNPJ / CPF
  - xNome
  - UF
  - cMun
  - xMun
  - indIEDest      → Indicador IE (1=Contribuinte, 2=Isento, 9=Não contribuinte)

  POR ITEM (det/prod + det/imposto):
  - nItem          → Número do item
  - cProd          → Código do produto
  - xProd          → Descrição
  - NCM            → Código NCM (8 dígitos)
  - CFOP           → Código fiscal (4 dígitos)
  - uCom           → Unidade comercial
  - qCom           → Quantidade
  - vUnCom         → Valor unitário
  - vProd          → Valor total do produto
  - vDesc          → Desconto
  - vFrete         → Frete rateado

  ICMS POR ITEM:
  - orig            → Origem da mercadoria
  - CST / CSOSN    → Código de situação tributária
  - modBC          → Modalidade base de cálculo
  - vBC            → Base de cálculo
  - pICMS          → Alíquota declarada
  - vICMS          → Valor declarado
  - pRedBC         → Redução de base (se houver)
  - vICMSST        → Valor ST (se houver)
  - vBCST          → Base de cálculo ST

  PIS/COFINS POR ITEM:
  - CST
  - vBC
  - pPIS / pCOFINS → Alíquotas declaradas
  - vPIS / vCOFINS → Valores declarados

  IPI POR ITEM (se houver):
  - CST
  - vBC
  - pIPI
  - vIPI

  TOTAIS DA NOTA (ICMSTot):
  - vBC, vICMS, vICMSDeson, vFCPST, vST
  - vProd, vFrete, vSeg, vDesc, vII, vIPI
  - vPIS, vCOFINS, vNF

  FUNÇÃO PRINCIPAL:
  def parse_xml(caminho_arquivo: str) -> dict
  def parse_multiplos_xml(lista_caminhos: list) -> pd.DataFrame
  def extrair_itens(nfe_dict: dict) -> pd.DataFrame

  TRATAMENTO DE ERROS:
  - XML malformado → retornar erro com nome do arquivo
  - NFe cancelada (evento de cancelamento) → marcar flag "cancelada"
  - Layout diferente de 4.0 → tentar compatibilizar ou alertar

MÓDULO 2: MOTOR DE VALIDAÇÃO (core/motor_validacao.py)
================================================================================

OBJETIVO: Cruzar os dados da NFe com as regras tributárias corretas e apontar
divergências com grau de severidade.

GRAUS DE SEVERIDADE:
  - CRÍTICO    → Impacto financeiro alto, possível autuação
  - ALERTA     → Inconsistência relevante que precisa de análise
  - INFORMATIVO → Divergência pequena ou questão de conformidade

VALIDAÇÕES A IMPLEMENTAR:

  [V01] CFOP vs TIPO DE OPERAÇÃO
  - CFOP 1xxx/2xxx = Entrada | 3xxx = Entrada exterior
  - CFOP 5xxx/6xxx = Saída   | 7xxx = Saída exterior
  - Cruzar com campo tpNF (0=Entrada, 1=Saída)
  - Severidade: CRÍTICO se divergente

  [V02] CFOP vs DESTINO (idDest)
  - idDest=1 (Interna)       → CFOP deve ser 1xxx ou 5xxx
  - idDest=2 (Interestadual) → CFOP deve ser 2xxx ou 6xxx
  - idDest=3 (Exterior)      → CFOP deve ser 3xxx ou 7xxx
  - Severidade: CRÍTICO

  [V03] ALÍQUOTA ICMS DECLARADA vs ALÍQUOTA ESPERADA
  - Buscar alíquota correta em config/aliquotas_icms.json por:
      * UF emitente + UF destinatário (operações interestaduais)
      * UF emitente (operações internas)
  - Comparar com pICMS declarado na nota
  - Tolerância: 0.01% (diferenças de arredondamento)
  - Severidade: CRÍTICO se diferença > 1%, ALERTA se menor

  [V04] BASE DE CÁLCULO ICMS
  - Verificar se vBC está correto:
      vBC = vProd + vFrete + vSeg - vDesc + vOutro (conforme modBC)
  - Para modBC=3 (Pauta): não validar automaticamente
  - Severidade: ALERTA se divergência > R$ 1,00

  [V05] VALOR DO ICMS CALCULADO vs DECLARADO
  - vICMS_calculado = vBC * pICMS / 100
  - Comparar com vICMS declarado
  - Severidade: CRÍTICO se divergência > R$ 1,00

  [V06] CST vs REGIME TRIBUTÁRIO (CRT)
  - CRT=1 (Simples Nacional) → deve usar CSOSN (1xx), não CST (0xx-9x)
  - CRT=3 (Normal) → deve usar CST, não CSOSN
  - Severidade: CRÍTICO

  [V07] CFOP vs CST DE PIS/COFINS
  - CFOPs de revenda (ex: 5102, 6102) + CST 50 = possível crédito indevido
  - CST 01/02/03 = tributação com crédito, verificar se CFOP permite
  - Carregar regras do arquivo config/cst_pis_cofins.json
  - Severidade: ALERTA

  [V08] ALÍQUOTA PIS/COFINS
  - Regime Normal:
      PIS:    1,65% (não-cumulativo) ou 0,65% (cumulativo)
      COFINS: 7,60% (não-cumulativo) ou 3,00% (cumulativo)
  - Simples Nacional: geralmente CST 07/08/09 (sem destaque)
  - Severidade: ALERTA se alíquota diferente do esperado pelo regime

  [V09] NCM vs ALÍQUOTA IPI
  - Buscar alíquota IPI esperada na TIPI via config/ncm_aliquotas.json
  - Comparar com pIPI declarado
  - Severidade: ALERTA

  [V10] DUPLICIDADE DE CHAVE DE ACESSO
  - Verificar se chNFe aparece mais de uma vez no lote de XMLs
  - Severidade: CRÍTICO

  [V11] NOTA FORA DO PRAZO DE EMISSÃO
  - dhEmi não pode ter mais de 24h de diferença da dhSaiEnt (data saída/entrada)
  - Severidade: INFORMATIVO

  [V12] SOMA DOS ITENS vs TOTAL DA NOTA
  - Somar vProd de todos os itens e comparar com total declarado
  - Tolerância de R$ 0,02 (arredondamento)
  - Severidade: CRÍTICO se divergência > R$ 0,02

  RETORNO DA FUNÇÃO:
  def validar_nfe(nfe_df: pd.DataFrame) -> pd.DataFrame
    → Retorna DataFrame com colunas:
       chNFe, nNF, item, codigo_validacao, descricao, valor_declarado,
       valor_esperado, divergencia, severidade

MÓDULO 3: ALÍQUOTAS EM TEMPO REAL (core/atualizador_aliquotas.py)
================================================================================

OBJETIVO: Garantir que o sistema use sempre as alíquotas vigentes.

FONTES DE ATUALIZAÇÃO:

  1. ICMS INTERESTADUAL (CONFAZ)
     - Alíquotas padrão CONFAZ:
         * 4%  → operações com bens importados (Resolução SF 13/2012)
         * 7%  → Sul/Sudeste → Norte/Nordeste/Centro-Oeste + ES
         * 12% → demais interestaduais
     - Alíquotas internas por UF: variam de 17% a 22%
     - Implementar tabela hardcoded + possibilidade de atualização manual
     - Endpoint sugerido para verificação futura:
         CONFAZ: https://www.confaz.fazenda.gov.br/legislacao/convenios

  2. ISS POR MUNICÍPIO
     - ISS varia de 2% (mínimo LC 116/2003) a 5% (máximo)
     - Fonte: APIs municipais ou tabela por código IBGE
     - Implementar função:
         def buscar_iss_municipio(codigo_ibge: str) -> float
     - Usar arquivo config/aliquotas_iss.json como base
     - Cobrir os 100 maiores municípios obrigatoriamente
     - Para municípios não mapeados: retornar 5% com flag "estimativa"

  3. PIS/COFINS
     - Alíquotas fixas por lei — atualizar apenas se houver mudança legislativa
     - Manter controle de vigência com data_inicio e data_fim em JSON

  4. TABELA TIPI (IPI)
     - Atualização via arquivo JSON local baseado na TIPI vigente
     - Função para buscar alíquota por NCM:
         def buscar_aliquota_ipi(ncm: str) -> float
     - Implementar cache em memória para performance

  5. SIMPLES NACIONAL
     - Faixas de receita bruta e alíquotas por anexo (I a V)

MÓDULO 4: APURAÇÃO DE IMPOSTOS (core/apuracao.py)
================================================================================

OBJETIVO: Calcular débitos, créditos e saldo a recolher por período fiscal.

  APURAÇÃO ICMS:
  def apurar_icms(df_notas: pd.DataFrame, periodo: str) -> dict
  - Filtrar notas pelo período (mês/ano)
  - DÉBITOS: somar vICMS de notas de saída (CFOP 5xxx/6xxx)
  - CRÉDITOS: somar vICMS de notas de entrada com direito a crédito
      * CFOPs que geram crédito: 1xxx (compras para revenda/insumo)
      * CFOPs que NÃO geram crédito: uso/consumo, ativo imobilizado (regra ICMS)
  - Retornar: {debitos, creditos, saldo_devedor, saldo_credor}

  APURAÇÃO PIS/COFINS (regime não-cumulativo):
  def apurar_pis_cofins(df_notas: pd.DataFrame, periodo: str) -> dict
  - DÉBITOS: saídas tributadas (CST 01, 02, 05, 06)
  - CRÉDITOS: entradas com CST 50, 51, 55, 60, etc.
  - Retornar separado: {pis: {debitos, creditos, saldo}, cofins: {...}}

  APURAÇÃO ISS:
  def apurar_iss(df_servicos: pd.DataFrame, periodo: str) -> dict
  - Para NFSe (Nota de Serviço): calcular ISS sobre base de serviços
  - Alíquota baseada no município do prestador
  - Retenção na fonte: verificar se o tomador deve reter

  RELATÓRIO DE APURAÇÃO:
  - Tabela resumo por imposto
  - Comparativo mês a mês (últimos 12 meses se disponível)
  - Identificar meses com saldo credor acumulado

MÓDULO 5: DETECTOR DE ANOMALIAS (core/detector_anomalias.py)
================================================================================

OBJETIVO: Identificar padrões suspeitos que fogem do comportamento esperado.

  [A01] NOTAS DE ALTO VALOR SEM HISTÓRICO
  - Nota com valor > 3x a média do emitente no período
  - Flag para análise manual

  [A02] SEQUÊNCIA DE NOTAS COM SALTO NUMÉRICO
  - Identificar gaps na numeração (ex: notas 100, 101, 105 — faltam 102/103/104)
  - Pode indicar notas canceladas não declaradas

  [A03] MESMO CNPJ EMITINDO EM MÚLTIPLOS ESTADOS
  - Verificar se emitente tem IE em todos os estados onde emite
  - Cruzar UF da nota com UF do CNPJ

  [A04] CFOP DE DEVOLUÇÃO SEM NOTA ORIGINAL
  - CFOPs 1201/1202/5201/5202 devem ter referência à nota devolvida
  - Verificar campo refNFe no XML

  [A05] PRODUTO COM NCM INCOMUM PARA O SEGMENTO
  - Cruzar NCM com CNPJ CNAE (se disponível) para detectar incongruências

  [A06] CONCENTRAÇÃO EXCESSIVA EM UM FORNECEDOR
  - Fornecedor com > 40% do total de compras do período
  - Possível operação simulada ou dependência tributária

  [A07] NOTAS EMITIDAS FORA DO HORÁRIO COMERCIAL
  - Emissão entre 22h-6h pode ser indicativo de fraude
  - Apenas para operações com consumidores finais

REGRAS TRIBUTÁRIAS IMPORTANTES A IMPLEMENTAR
================================================================================

ICMS:
  - Diferencial de alíquota (DIFAL): EC 87/2015
      * Operações interestaduais para consumidor final não contribuinte
      * Partilha DIFAL entre UF origem e destino (ver tabela por ano)
  - FCP (Fundo de Combate à Pobreza): adicional de 2% em alguns estados
      * MG, RJ, CE, MA, PI, AL, RN, SE, TO, AP, RO, AC, AM, PA, RR, MT, MS
  - Substituição Tributária (ST): identificar por CFOP e NCM
  - Simples Nacional: empresa no Simples não destaca ICMS — CST deve ser CSOSN

PIS/COFINS:
  - Regime Cumulativo (Lucro Presumido):   PIS 0,65% | COFINS 3,00%
  - Regime Não-Cumulativo (Lucro Real):    PIS 1,65% | COFINS 7,60%
  - Monofásico: alíquotas diferenciadas por NCM (combustíveis, farmácia, etc.)
  - Substituição PIS/COFINS: identificar por CST 04/05/06

IPI:
  - Alíquotas pela TIPI (Tabela de Incidência do IPI)
  - Estabelecimentos industriais e equiparados ao industrial
  - IPI não incide para Simples Nacional em saídas (exceto importação)

ISS:
  - Alíquota mínima: 2% (LC 116/2003, art. 8-A)
  - Alíquota máxima: 5%
  - LOCAL DO SERVIÇO define qual município cobra:
      * Regra geral: município do estabelecimento prestador
      * Exceções (Lista Anexo LC 116): município onde o serviço é executado
        (construção civil, eventos, etc.)
  - Retenção na fonte: tomador retém quando for PJ e alíquota >= 2%

# Sistema de Auditoria Fiscal Automatizada de NFe

## O que é
Sistema profissional para auditoria de Notas Fiscais Eletrônicas...

## Tecnologias
Python 3.11 · Streamlit · Pandas · lxml · Plotly · openpyxl

## Funcionalidades
- [ ] Upload e parse de XMLs NFe (layout 4.0)
- [ ] 12 validações tributárias automatizadas
- [ ] Alíquotas ICMS por estado (CONFAZ)
- [ ] Alíquotas ISS por município (100+ municípios)
- [ ] Apuração ICMS, PIS/COFINS, ISS por período
- [ ] Detector de 7 anomalias fiscais
- [ ] Exportação em Excel e PDF

## Como executar
pip install -r requirements.txt
streamlit run app.py
